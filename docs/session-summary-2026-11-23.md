# 개발 세션 정리 (2026-11-22 ~ 11-23)

한·영·일 자동 전환 IME를 기획부터 Windows에서 실제로 쓰는 수준까지 만든 세션의 요약. 세부 측정·경위는 `README.md`, 남은 일은 `docs/next-tasks.md`, 설계는 `docs/v1-tsf-frontend.md`.

## 1. 기획과 방향 (사용자 결정)

- 공개용 다국어 IME. 고유 기능: 미리 정한 언어 사이 자동 전환, 자동 등록·편집 가능한 사용자 사전.
- 모델: 일본어 IME의 변환 방식(조합 → 1위 자동 → 후보 순환 → 확정 시 학습)을 다국어로 넓히고 언어 판정을 얹는다.
- v1 = 한·영·일 (Windows TSF + Mozc). 중국어는 v3. 무료 배포, GPL-3.0 전제.
- 키 설계: Space = 확정만(변환과 분리), 왼쪽 Shift 탭 = 변환/다음 후보, 숫자 1~5 고르기, Enter 확정, Backspace = 후보창 있으면 친 키 그대로 / 없으면 키 하나 지우기. 확정한 단어 다시 열기는 두지 않는다.
- 기획서: claude.ai Doc "다국어 자동 전환 IME 기획서" (https://claude.ai/artifact/KC3BDnzMf6JEacSz6gG9yK).

## 2. 언어 판정 엔진

- Python v0 → Rust 이식 (`engine/`, Python과 1,500문장 일치 확인 후 의도적으로 분기).
- 키 입력 4-gram 언어 모델 + wordfreq 사전 + 두벌식 오토마타 + 로마자 파서, 토큰 안 언어 격자(k-best), 문장 Viterbi, 직전 단어 언어 가중치(MOMENTUM 0.3), 전부 대문자는 영어, 대소문자 기억, 사용자 학습 기록.
- 평가: 공개 데이터(Leipzig 뉴스·위키·웹, Tatoeba, NSMC)와 사용자 트윗(비공개, git 제외). 왼쪽 문맥만 쓰는 실제 IME 조건은 문장 전체 판정보다 오판 1.2~3배.
- 영단어 + 일본어 조사 분할 규칙 (패턴 세트 26→36/43, 공개 데이터 변화 없음). 남은 실패(`mailwookutta` 등)는 실사용에서 쓰지 않는 형태라 우선순위 낮음 (일본어 입력 중엔 メール로 친다).

## 3. 프로그램 구조

- `tip/` TSF 텍스트 서비스 DLL (Rust, windows 0.62, x64·x86 빌드). 앱 안에서 키를 받아 백엔드에 묻고 조합·확정·후보창을 그린다.
- `backend/` 사용자당 하나 상주 (작업 스케줄러 "MultilangIME Backend"로 로그온 시작). 이름 있는 파이프(JSON). 판정·조합·후보·학습·Mozc 연결.
- `mozc/` Mozc 파이프 클라이언트 (prost). 배포는 공식 MSI에서 꺼낸 `mozc_server.exe`를 `deploy\x64\mozc\`에 둔다. 백엔드 시작 때 백그라운드로 미리 띄운다.
- `ipc/` 요청·응답 형식. `deploy\x64\` 실행 파일·모델·한자 사전(libhangul `hanja.txt`, BSD-3).
- 설정 `%LOCALAPPDATA%\multilang-ime\settings.json` (`ja_space`), 학습 `history.json`, `hanja_learn.json`.

## 4. 기능 (모두 메모장 등에서 실측)

- 한·영·일 자동 전환 입력, 구간별 밑줄(일반/모호/고르는 중).
- 일본어: 가나가 완성되면 Mozc 변환 결과로 라이브 표시, 확정 시 Mozc 학습. 키당 지연 최대 3 ms (새 키만 보내기). 영단어 뒤 일본어는 これ 자리표시로 변환(`Youtubeに動画を上げた`).
- 후보창: 문맥과 상관없이 언어 묶음(영어+전각 / 한국어+한자 / 일본어 Mozc), Shift 탭·↑↓·숫자·Tab(묶음 이동).
- 부분 변환: 긴 입력을 언어 구간·Mozc 문절로 나눠 ←/→로 부분 이동, 부분마다 후보.
- 한국어 발음 → 한자 후보 (단어 단위, 선택 학습).
- 기호·숫자 조합과 Shift 탭 변형(。、「」, →, ③ 등), 일본어 문맥 기호, `-`→ー.
- 공백: 일본어 문맥 Space = 확정 + 전각 공백(기본) / `"ja_space": "continue"`면 이어서 변환. 조합이 없을 때 Space는 보통 공백, Shift+Space = 전각 공백.
- 안정성: 응답 지연·백엔드 재시작 때 조합 유지(키 기록과 되살리기), Mozc 미리 띄우기.
- 자동 꺼짐: 비밀번호·숫자·전화·이메일·URL 칸(입력칸 용도), 꺼진 문맥, 옛 Edit 스타일.
- 옛 Win32 입력칸(CUAS): 한국어 프로필에서 조합 글자를 한 글자만 허용해 키마다 끊기던 문제 → 조합을 커서 아래 조합 창에 보이고 확정만 넣는다. 판별은 Edit/WinForms 창 클래스 + 문자표용 보조 조건 (Codex가 좁힘).
- 샌드박스 앱(작업 표시줄 검색창): 배포 폴더 읽기 권한 + 파이프 보안(이 사용자 + AppContainer, 무결성 Low)으로 입력 가능. 후보 목록 UI 요소(ITfCandidateListUIElement)도 알림 (UI-less 앱용).

## 5. 확인된 한계와 결정

- 메모장 일본어 글자(気·ー) 깨짐: 메모장은 입력 프로필 언어로 글꼴을 고른다. 프로필 전환·언어 속성·가짜 입력 언어 알림은 효과 없음 → 한·일 글자가 다 있는 글꼴(Noto Sans KR) 안내로 확정 (사용자 확인).
- Mozc 앞 문맥 넘기기: 효과 없음. 문장 통째 변환이 낫다 → 설정 옵션(`continue`)으로 제공, 기본은 확정.
- 작업 표시줄 검색창 후보창: 창은 떠 있지만 셸 검색 화면이 더 높은 창 층(band)에 있어 가려진다. UI 요소 방식도 검색창이 "IME가 그려라"로 답해 해결 안 됨 → 별도 후보창 프로세스 + UIAccess (서명·Program Files 설치 필요)로 배포 준비 때 처리.
- 시험하며 확정한 일본어는 실제 Mozc 학습에 남는다 → 시험은 Esc로 취소, 오염되면 `mozc_clear`를 작업 스케줄러로 실행.

## 6. 참고 조사

- Meltype (GPL-3.0, 일·영만): Mozc 도우미 프로세스, 영어 판정 자원, Zenzai(zenz + llama.cpp). GPL-3.0이면 참조·일부 재사용 가능. 비교 브랜치는 나중에. 로컬 AI는 품질 이득이 클 때만 선택 기능으로.
- Microsoft IME 요구사항 검토 (`docs/ime-requirements-compatibility-review.md`): 코드 서명, x86 배포, 파이프 ACL(해결), UI-less, 터치 키보드, 트레이 아이콘.

## 7. 환경 메모

- 기본 입력 방법을 우리 IME로 설정 (Meltype 설치가 Meltype으로 바꿔 두었음). Codex가 MS 일본어·우리 일본어·Meltype 프로필을 사용자 설정에서 숨김.
- 배포 교체: TIP가 백엔드를 바로 다시 띄우므로 실행 중 파일 이름을 바꾸고 새 파일을 넣는다. 새 DLL은 앱을 다시 열어야 적용. 이전 판은 `deploy\x64\old\`.
- 진단: `deploy\x64\MULTILANG_TIP_DEBUG` 파일 → `deploy\x64\logs\tip-debug.log` (샌드박스 앱도 기록 가능).
- Claude 데스크톱 셸은 패키지 앱 문맥이라 실제 `%LOCALAPPDATA%`가 가려 보인다. 실제 위치에 쓸 때는 1회성 예약 작업을 쓴다.
